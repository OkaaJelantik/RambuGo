# Implementasi: Scene Berjalan 2.5D (Kids-Interactive, Mobile-First)

Spec (otoritas): `docs/superpowers/specs/2026-11-07-petualangan-rambu-lalu-lintas-design.md`
Baseline: prototipe 6-stage sudah jalan. Yang diganti hanya scene berjalan (`Journey`).

## Konteks

Scene berjalan sekarang terasa cacat karena: (1) "berjalan" = 3 lompatan `transition 1.2s`,
bukan gerak; (2) pohon = `radial-gradient` blob, rumah cakrawala = `<span>` + atap `border`;
(3) jalan digambar dengan `clip-path` linear sementara objek ditempatkan dengan
`proj()` hiperbolik — tepi jalan dan posisi objek tidak pernah cocok; (4) hero
menghadap penonton padahal berjalan menjauh; (5) tidak ada kendaraan/pejalan.
Bar desain: **"hidup dan lucu" ala web interaktif anak**, bukan realistis.

## Global Constraints (mengikat semua task)

1. **Mobile-first.** Baseline layout potret 360×640. Media query hanya `min-width` untuk
   layar lebih lebar; jangan menambah `max-width` baru. Target utama 1 anak 1 HP.
2. **Art = komponen SVG inline.** Tidak ada file gambar biner. Palet hanya token yang
   sudah ada di `src/index.css` (`--ink`, `--sky-*`, `--grass*`, `--road*`, `--red`,
   `--yellow`, `--blue`, `--orange`, `--green`). Warna baru hanya boleh turunan
   (lighten/darken) dari token itu.
3. **Semua teks untuk anak berbahasa Indonesia**, ragam anak kelas II SD: kalimat pendek,
   satu ide per kalimat, tanpa istilah teknis.
4. **Mobile 60fps.** Dalam scene: nol `filter`, nol `backdrop-filter`, nol `blur`,
   maksimal 30 objek beranimasi, dan tidak ada pembacaan layout (`offsetTop`,
   `getBoundingClientRect`) di dalam loop animasi.
5. **Gerak kontinu lewat satu loop `requestAnimationFrame`** yang memanggil reducer murni
   `stepWorld(state, dt)` (tanpa DOM read) lalu menulis `style.transform` dari ref.
   Tidak ada `setState` per frame. Loop berhenti saat tab `hidden`.
6. **`prefers-reduced-motion: reduce`** → dunia statis (loop tidak mulai), tanpa
   kendaraan/NPC, rambu tetap bisa ditekan.
7. **Touch target rambu ≥ 56×56 px.**
8. **TypeScript strict, `tsc -b` bersih, `vite build` bersih, `pnpm test` hijau.**
9. **Tidak ada dependensi runtime baru.** Dev-only: `vitest`, `jsdom`,
   `@testing-library/react`, `@testing-library/dom`.
10. **Kontrak `App.tsx` dipertahankan**: `WalkScene` menerima `step: number` dan
    `onOpen(sign: Sign)`; tiga rambu berjalan tetap `WALK_SIGNS`.
11. Setiap task diakhiri satu commit. Jangan mengubah spec kecuali Task 9.

## Angka acuan (dipakai lintas task, jangan diubah tanpa catatan di report)

```
HORIZON      = 0.38      // fraksi tinggi viewport, garis cakrawala
DEPTH_K      = 9         // scaleAt(d) = 1 / (1 + DEPTH_K * d)
ROAD_HALF    = 0.30      // setengah lebar jalan pada d = 0 (fraksi lebar viewport)
WALK_W       = 0.10      // lebar trotoar (fraksi lebar viewport, pada d = 0)

```

## Task 1 — Tooling test + modul proyeksi

**Goal:** fondasi angka yang bisa diuji sebelum ada UI.

**Files:** `.gitignore` (sudah ada), `package.json`, `vite.config.ts`, `src/scene/projection.ts`,
`src/scene/projection.test.ts`, `src/test/setup.ts`.

**Requirements**

1. `devDependencies`: `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/dom`.
   Script `"test": "vitest run"`, `"test:watch": "vitest"`.
2. Konfigurasi test di `vite.config.ts` (blok `test`: `environment: 'jsdom'`,
   `setupFiles: ['./src/test/setup.ts']`, `globals: true`). Tambahkan
   `src/test/setup.ts` berisi `import '@testing-library/dom'`-compatible cleanup
   (panggil `cleanup` dari `@testing-library/react` di `afterEach`).
3. `src/scene/projection.ts` mengekspor, sebagai fungsi murni tanpa import React:

```ts
export const HORIZON = 0.38
export const DEPTH_K = 9
export const ROAD_HALF = 0.3
export const WALK_W = 0.1
export const LANES = { sidewalkL: -0.4, laneL: -0.2, laneR: 0.2, sidewalkR: 0.4 }

export function scaleAt(depth: number): number      // 1 / (1 + DEPTH_K * depth)
export function yAt(depth: number): number          // HORIZON + (1 - HORIZON) * scaleAt(depth)
export function xAt(offset: number, depth: number): number  // 0.5 + offset * scaleAt(depth)
export function fadeAt(depth: number): number       // 0 di depth >= 0.92, 1 di depth <= 0.62, linear di antaranya
export function roadHalfAt(depth: number): number   // ROAD_HALF * scaleAt(depth)
export function walkHalfAt(depth: number): number   // (ROAD_HALF + WALK_W) * scaleAt(depth)
```

   Semua menerima `depth` 0..1 (0 = di kaki kamera, 1 = cakrawala) dan mengembalikan
   fraksi 0..1 dari viewport. Depth di luar rentang di-clamp.

**Tests (`projection.test.ts`)**

- `scaleAt(0) === 1`, `scaleAt(1)` mendekati `1/(1+DEPTH_K)` (toleransi 1e-9)
- `scaleAt` monoton menurun; `yAt` monoton menurun; `yAt(0) === 1`; `yAt(1) < 0.46`
- `xAt(-0.4, 0) === 0.1` dan `xAt(0.4, 0) === 0.9`; `xAt(0, d) === 0.5` untuk semua d
- `fadeAt(0) === 1`, `fadeAt(1) === 0`, tidak monoton naik di rentang 0.62..0.92
- `roadHalfAt(0) === ROAD_HALF`
- Depth di luar 0..1 di-clamp (`scaleAt(-1) === 1`, `scaleAt(2) === scaleAt(1)`)

**Acceptance:** `pnpm test` hijau; `tsc -b` bersih; tidak ada file UI disentuh.

**Commit:** `feat(scene): modul proyeksi + tooling vitest`

## Task 2 — Lapisan dunia statis (`GroundScene`)

**Goal:** jalan, trotoar, dan verge digambar dari fungsi proyeksi yang sama, sehingga
tepi jalan cocok dengan posisi objek di kedalaman mana pun.

**Files:** `src/scene/GroundScene.tsx`, `src/scene/GroundScene.test.tsx`, `src/walk.css`.

**Requirements**

1. Komponen `<GroundScene />` hanya latar, `aria-hidden`, tanpa props.
2. Struktur: `<div class="wk-ground">` berisi, dari bawah ke atas: `.wk-sky`
   (gradient token sky), `.wk-hills` (2-3 siluet bukit, warna `--grass` turunan),
   `.wk-haze` (pita gradient putih → transparan, menutup 0.5% di bawah cakrawala),
   `.wk-verge`, `.wk-walk-left`, `.wk-walk-right`, `.wk-road`, `.wk-edge-l`.
   `.wk-edge-r` (garis tepi jalan putih).
3. **Geometri wajib dihitung dari proyeksi**, bukan `clip-path` manual: bangun
   `<svg viewBox="0 0 100 100" preserveAspectRatio="none">` dan gambar jalan sebagai
   `<polygon>` dengan titik: `(50 - roadHalfAt(0)*100, 100)`,
   `(50 + roadHalfAt(0)*100, 100)`, `(50 + roadHalfAt(1)*100, yAt(1)*100)`,
   `(50 - roadHalfAt(1)*100, yAt(1)*100)`. Trotoar memakai `walkHalfAt`. Catat di
   komentar: karena y lineer terhadap `scaleAt`, tepi jalan memang garis lurus —
   poligon ini setara dengan proyeksi objek.
4. Tinggi cakrawala memakai `HORIZON` dari modul proyeksi (jangan hardcode 38).
5. `walk.css`: semua kelas berprefix `wk-`; baseline mobile (tidak ada `max-width`);

6. Tanpa `filter`/`blur`/`backdrop-filter`.

**Tests (`GroundScene.test.tsx`)**

- Render dan pastikan `.wk-road polygon` ada, memakai `points` yang mengandung
  `yAt(1)*100` (bukan angka hardcode)
- `roadHalfAt(1) < roadHalfAt(0)` → lebar jalan di puncak lebih sempit dari di dasar
  (assert dari atribut `points`, toleransi 0.01)

**Acceptance:** terlihat utuh di 360×640 dan 1024×600; tepi jalan lurus dan cocok
dengan objek yang dijanjikan akan ditaruh Task 4; `pnpm test` hijau.

**Commit:** `feat(scene): lapisan dunia statis dari modul proyeksi`

## Task 4 — `WalkScene`: mode walking/stopped, loop dunia, rambu

**Goal:** scene berjalan yang hidup, menggantikan `Journey`.

**Files:** `src/WalkScene.tsx`, `src/scene/world.ts`, `src/scene/world.test.ts`,
`src/walk.css`, `src/App.tsx`; hapus `src/Journey.tsx` dan `src/journey.css`.

**Requirements**

1. `src/scene/world.ts` — state dan reducer murni, tanpa DOM/React:

```ts
export type Mode = 'walking' | 'stopped'
export type WorldState = {
  mode: Mode
  travel: number        // detik sejak leg dimulai
  scroll: number        // offset dunia dalam satuan kedalaman, bertambah tiap detik
  step: number          // index rambu yang sedang aktif (0..2)
}
export function createWorld(step: number): WorldState
export function stepWorld(s: WorldState, dt: number): WorldState   // murni
```
   Aturan: mode `walking` menambah `scroll` sebesar `SCROLL_PER_SEC` (= 0.55 depth/detik);
   setelah `travel >= LEG_SECONDS` berpindah ke `stopped` dan `scroll` berhenti.
   Fungsi tidak boleh punya efek samping dan harus mengembalikan objek baru hanya bila
   nilainya berubah.
2. `WalkScene` menerima `{ step, onOpen }`. Di dalamnya:
   - `useRef` untuk elemen pita: 8 marka jalan, 6 objek latar (dari art kit Task 3,
     dipakai berulang), hero.
   - Satu `requestAnimationFrame` loop memanggil `stepWorld` lalu menulis
     `style.transform = translate3d(x, y, 0) scale(s)` untuk tiap entri; posisi
     dihitung dengan `xAt`/`yAt`/`scaleAt` dan **dibulatkan ke 0.5px** untuk mengurangi
     penulisan. Tidak ada `setState` di loop; `mode` yang berubah dipantau dengan
     `useState` hanya saat transisi (walking→stopped dan sebaliknya).
   - Loop berhenti bila `document.hidden`.
   - `prefers-reduced-motion: reduce` → loop tidak pernah mulai dan `mode` langsung
     `stopped` untuk setiap `step`, sehingga rambu selalu bisa ditekan tanpa perlu
     menunggu perjalanan; menutup sheet langsung memajukan `step` berikutnya.
   - Rambu aktif: `WALK_SIGNS[step]` ditempatkan pada `SIGN_STOP_D` setelah mode
     `stopped`, tombol `<button>` ≥56px, `aria-label` Indonesia, memakai `SignArt`.
     Rambu yang sudah lewat (`i < step`) tidak dirender.
   - Balon ucapan hero memakai tiga kalimat yang sudah ada di `Journey.tsx` (pindahkan
     konstanta `LINES`).
   - HUD `pv-hud` diganti `wk-hud` (teks "Jalan ke jalan raya" + pips 3 titik).
3. `App.tsx`: impor `WalkScene`, hapus impor `Journey`. Kontrak `step`/`onOpen` tetap.
4. Hapus `Journey.tsx` dan `journey.css`. Tidak ada CSS `pv-*` tersisa di repo.

**Tests (`world.test.ts`)**

- `createWorld(0)` → mode `walking`, scroll 0
- `stepWorld` menambah scroll sebesar `0.55 * dt` (toleransi 1e-9)
- Setelah total `dt` mencapai `LEG_SECONDS` → mode `stopped`, dan `stepWorld` lagi
  tidak menambah scroll
- `stepWorld` tidak memutasi objek input
- `dt` besar (mis. 5 detik) tetap menghasilkan mode `stopped`, bukan overshoot

**Acceptance:** alur intro → walk → crossroad jalan; tiga rambu muncul berurutan;
marka dan objek bergerak kontinu (bukan 3 lompatan); tidak ada `filter` di scene.

**Commit:** `feat(scene): WalkScene 2.5D menggantikan Journey`

3. `src/scene/spawner.ts` — RNG deterministik + penjadwal murni:

```ts
export function createRng(seed: number): () => number     // mulberry32, 0..1
export type Traffic = { id: number; lane: 'laneL' | 'laneR'; kind: 'car' | 'bike'; depth: number; speed: number; dir: 1 | -1 }
export type Ped = { id: number; lane: 'sidewalkL' | 'sidewalkR'; kind: 'adult' | 'child'; depth: number; speed: number }
export function spawnTraffic(rng: () => number, nextId: number): Traffic   // depth mulai 1.0
```

   `requestAnimationFrame` yang sama dengan loop dunia. Objek didaur ulang saat
   `depth < -0.05` atau `> 1.05`. Semua elemen dekoratif `pointer-events: none`.
5. `prefers-reduced-motion`: tidak ada spawn sama sekali.

**Tests (`spawner.test.ts`)**

- `createRng(42)` menghasilkan urutan yang sama pada dua instans (deterministik)
- Nilai RNG selalu di `[0, 1)`
- `spawnTraffic` memberi `depth === 1` dan `speed` di rentang 0.18–0.30
- `laneL` selalu `dir: -1`, `laneR` selalu `dir: 1`
- `shouldSpawn` benar untuk `sinceLast > max` dan salah untuk `sinceLast < min`

**Acceptance:** minimal satu kendaraan terlihat lewat setiap ≤10 detik saat mode
`walking`; tidak ada yang menghalangi tap rambu; reduced-motion → nol kendaraan.
